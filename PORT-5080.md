# RTX 5080 (16 GiB) port

The RTX 5080 and 5080 Laptop GPU are the same Blackwell `sm_120` family as the 5090, so every
kernel builds unchanged for `sm_120a`. What differs is memory and the driver line:

| | RTX 5090 | RTX 5080 Laptop |
|---|---|---|
| VRAM | 32 GiB | 16 GiB (15.54 GiB free on an idle Windows desktop) |
| SMs / L2 | 170 / 96 MiB | 60 / 64 MiB |
| Driver / CUDA | 590.x / CUDA 13.1 | 577.x / CUDA 12.9 max |
| OS | Linux | Windows 11 + WSL2 (Ubuntu 24.04) |

## What changed

1. **CUDA 12.8+ builds.** `cuda/cuda_abi.cu` maps the edge-data graph-capture calls used by the
   adaptive `{2,4,8}` switch graph to their CUDA 12 names (`cudaStreamGetCaptureInfo_v3`,
   `cudaGraphAddNode_v2`, `cudaStreamUpdateCaptureDependencies_v2`). CUDA 13 builds are unchanged.
   `cudaGraphCondTypeSwitch` and PDL are available from CUDA 12.8.
2. **Embed table on the host and nvfp4 by default below 24 GiB.** The BF16 embed table (0.86 GiB)
   moves to zero-copy pinned host RAM, as upstream already does above 512K context; `--embed-device`
   keeps it on the GPU. An unset `--mode` falls back to `nvfp4`, because the `fp8` (serve) and
   `exact` (generate/bench) defaults need more VRAM than a 16 GiB card has for weights alone.
3. **Context and KV fitted to free VRAM.** After the weights load, the CLI computes the runtime
   arena for the requested `--ctx` and `--kv` (`engine.runtime_vram_bytes_for`). If it does not fit,
   auto KV switches `fp8 -> q4`, then context shrinks to the largest multiple of 1024 that fits
   (floor 4096). An explicit `--ctx` or `--kv` that does not fit exits with the numbers instead.
4. **No silent paging.** Under WDDM (Windows and WSL2) a `cudaMalloc` past physical VRAM succeeds
   and pages to system RAM. The weight loader checks free VRAM first and exits if weights + load
   staging + reserve do not fit. Free VRAM comes from NVML (`libnvidia-ml.so.1`, the figure
   nvidia-smi shows), falling back to `cudaMemGetInfo`. Under WSL2 `cudaMemGetInfo` returns the WDDM
   residency budget: 14.61 GiB on an idle 5080 Laptop, where NVML reports 15.36 GiB and a 15.0 GiB
   allocation reads at 853 GB/s (full speed, no paging). `SQUID_VRAM_RESERVE_MIB` (default 384) is
   kept free for cuBLAS workspaces and graph instantiation.
5. **`-Dprefill-batch=512|1024|2048`.** Every prefill scratch buffer scales with the chunk size
   (2048 is upstream's default and costs ~0.7 GiB). 1024 frees 0.34 GiB for KV.
6. **8-CTA clusters where 16 do not fit.** A thread-block cluster must fit in one GPC. GB202 (RTX
   5090) has 16 SMs per GPC; the RTX 5080 Laptop (60 SMs) schedules clusters of at most 10 CTAs, and
   a 16-CTA launch fails with `cudaErrorInvalidClusterSize` (error 912). Global-attention decode now
   checks `cudaOccupancyMaxActiveClusters` once per kernel instance and runs the 8-CTA shape the
   local layers already use when 16 does not fit. The 16-CTA BF16 controller and router (fp8/exact
   modes, which do not fit 16 GiB anyway) exit with a message naming `--mode nvfp4` instead of a CUDA
   assert.

## Budget

On an idle 5080 Laptop under WSL2 the process sees 15.36 GiB free after creating its context.
Weights by mode, as the loader accounts them with the embed table on the host and no MTP head:
nvfp4 13.42 GiB, fp8 15.70 GiB, exact 17.59 GiB (exact keeps the embed table on the GPU). With the
MTP head nvfp4 is 13.75 GiB, which with the 384 MiB reserve leaves 1.22 GiB for the runtime arena;
at `-Dprefill-batch=1024` the CLI fits that to a 51,200-token context with q4 KV
(`[vram] Fitted to 1.22 GiB free: ctx 65536 -> 51200, kv fp8 -> q4`).

The model needs the card to itself: another process holding more than ~0.4 GiB of VRAM leaves too
little for the weights (13.75 GiB + 0.86 GiB load staging + reserve).

## Checks

`tests/switch_graph_smoke.cu` builds the adaptive `{2,4,8}` conditional-switch graph through the
same `squid_adaptive_graph_*` ABI the engine uses and drives each branch (build line in the file).
On the RTX 5080 Laptop (WSL2, CUDA 12.8 runtime, driver 577.05) it selects widths 2/4/8 and runs
bodies 0/1/2, and prints NVML free VRAM next to `cudaMemGetInfo`.

Real weights (`thinkingmachines/Inkling-2-Mini`, SHA-256 checked), this branch on upstream `fda96e9`,
`-Dprefill-batch=1024`, RTX 5080 Laptop under WSL2 with the card to itself, greedy, no `--mode`,
`--ctx` or `--kv` unless shown:

| command | result | card peak |
|---|---|---:|
| `generate` (falls back from exact to nvfp4, MTP off), 256 tokens | 106.6 tok/s, prefill 187 ms; coherent; first 33 greedy tokens identical to a build on upstream `3140b65` | 14,872 MiB |
| `bench --mode nvfp4 --mtp 7 --max-tokens 512 --runs 3` | median 165.3 tok/s (160.6-167.2) at a fixed 80 W, acc 59.7%, dl 2.70, prefill 79.6 ms (246.4 tok/s at up to 150 W, below) | 15,288 MiB |
| `serve` (falls back from fp8 to nvfp4, MTP 7, fitted ctx 51,200 / q4): 45,353-token prompt asking for a tag inserted at 60% depth | answer `MAGENTA-OTTER-4417`, prefill 14.5 s (3,127 tok/s), decode 165.8 tok/s | 15,590 MiB |
| same request again | 45,056 tokens from the prefix cache, prefill 340 ms, same answer | |
| `"stream": true` request | 85 SSE `data:` lines ending in `[DONE]` | |

Laptop decode speed follows the GPU's power state, so compare builds back to back. The table above
ran with the "NVIDIA Platform Controllers and Framework" device disabled, which fixes the limit at
the 80 W default; decode then ran with memory at 9,001 MHz (max 14,001). With the device enabled
(dynamic limit up to 150 W, memory at 13,700-14,001 MHz), `bench --mode nvfp4 --max-tokens 512 --runs 3`,
alternating a build on upstream `3140b65` and this branch in one session:

| | `3140b65` | this branch |
|---|---:|---:|
| `--mtp 0` | 130.2 tok/s (runs 157.3, 130.2, 82.3) | 165.7 tok/s (165.4-166.3) |
| `--mtp 7` | 173.3 tok/s (164.9-177.9), acc 68.0%, dl 3.19 | 246.4 tok/s (227.6-261.1), acc 55.7-64.1%, dl 2.76-3.30 |

On a 45K prompt `3140b65` measured 23.7 s prefill and 120.5 tok/s decode at the 147 W limit; this
branch's 14.5 s and 165.8 tok/s in the table above ran at the fixed 80 W.

## Build and run on Windows (WSL2)

Inside WSL2 Ubuntu 24.04 with the Windows NVIDIA driver (577+) and the CUDA 12.8 toolkit at
`/usr/local/cuda`, plus Zig 0.17.1:

```bash
zig build -Doptimize=ReleaseFast -Dprefill-batch=1024

./zig-out/bin/squid5090 serve /opt/models/inkling-2-mini \
  --host 0.0.0.0 --port 8000 --mode nvfp4 --mtp 7
```

Leave `--ctx` and `--kv` unset on the first run and read the `[vram]` lines for what was fitted.
Keep the model directory on the WSL ext4 disk (not `/mnt/c`): the loader reads 20.2 GB of
safetensors and 9P reads from Windows drives are several times slower.

The checkpoint is 20.2 GB on disk (19.53 GB main + 0.64 GB MTP), and the WSL virtual disk grows
on its host drive, so that drive needs the space free.
